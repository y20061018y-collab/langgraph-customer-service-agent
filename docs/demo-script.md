# 演示脚本（录制 60~90 秒 GIF 用）

演示界面：`docker compose up --build` 启动后打开 <http://localhost:8000/>（端口以 `.env` 的 `APP_PORT` 为准）。每条回复下方的"查看执行详情"可以展开，显示本轮调用的工具（工具名、参数、返回摘要）和检索到的知识库片段（文件名、相似度、是否降级）。

## 数据来源与"预期现象"的含义

- 订单数据来自 [`scripts/seed_data.py`](../scripts/seed_data.py) 的 `SEED_ORDERS`，容器启动时自动灌入。下面用到的订单：

  | 订单号 | 状态 | 物流 | 物流详情（seed 原文） |
  | --- | --- | --- | --- |
  | 12345 | 已发货 | 正常 | 快件已到达【上海转运中心】，预计明日送达 |
  | 9527 | 已发货 | 异常 | 快件在【广州转运中心】滞留超过 48 小时，物流轨迹未更新 |

- 政策内容来自 `knowledge/*.md`。
- **"预期现象"里，订单字段和政策原文是由数据决定的，一定会出现；"会调用哪些工具"依据 [`agent.py`](../agent.py) 的 system prompt 规则，是预期而非保证（真实模型，temperature=0，仍可能偶发偏离）；回复的具体措辞取决于模型，不写死。** 录制前建议先自己跑一遍，不符合预期的对话换一种问法或重录。
- 相似度的具体数值取决于真实 embedding 接口，本文不预设，以界面显示为准（未确认）。
- 对话 2 会**真实写入一条工单**，见文末清理方法。
- 每条对话开始前点右上角"新会话"，避免上下文串扰。

---

## 对话 1：正常查询（约 10 秒）

**输入**：`帮我查一下订单12345`

**预期现象**
- 工具调用：只有 `query_order`，参数 `order_id` 为 `12345`；没有 `create_ticket`。
- 工具返回里能看到：状态"已发货"、物流状态"正常"、物流详情"快件已到达【上海转运中心】，预计明日送达"。
- 回复用自然语言转述上述信息（措辞取决于模型），不会建工单。
- "检索到的知识库片段"一栏显示"本轮没有检索知识库"。

**镜头重点**：展开执行详情，指出"工具返回的就是数据库里的真实记录"。

## 对话 2：物流异常 → 建工单（约 25 秒，两轮）

**输入（第 1 轮）**：`帮我查一下订单9527`

**预期现象**
- 工具调用：`query_order`（`order_id` 为 `9527`）。工具返回里物流状态为"异常"，详情为"快件在【广州转运中心】滞留超过 48 小时，物流轨迹未更新"。
- 按 system prompt 的建单规则，用户没有要求建单时只解释和建议，**不会主动建单**；可能会同时调用 `search_knowledge` 确认规则（`07-物流异常处理`，其中写明"超过 48 小时未更新，视为物流异常"），也可能不调用。

**输入（第 2 轮，同一会话）**：`帮我建个工单人工跟进`

**预期现象**
- 工具调用：`create_ticket`，`order_id` 为 `9527`（从上一轮上下文继承，不需要重新输入订单号）。
- 工具返回里有自增的 `ticket_id`、`status` 为"待处理"；回复里告知用户工单号。

**镜头重点**：先展示"只查不建"（不越权写库），再展示"用户明确要求后才建单"，并展开看 `create_ticket` 的参数。

## 对话 3：政策问题，展示检索来源（约 15 秒）

**输入**：`开增值税专用发票需要提供哪些资料？`

**预期现象**
- 工具调用：`search_knowledge`；没有 `query_order` 和 `create_ticket`。
- 检索片段一栏：状态"命中 · 未降级"，片段来源应包含 `11-发票政策`（可能还有其他相关文件，以界面为准）。
- 该文档的原文写明专票需要：公司抬头、纳税人识别号、注册地址及电话、开户行及账号，开票周期 3-5 个工作日。回复应基于这些内容（措辞取决于模型）。

**镜头重点**：展开"检索到的知识库片段"，指出文件名和相似度——回答有出处，可追溯。

## 对话 4：订单不存在 / 超出范围（约 20 秒，两轮，各点一次"新会话"）

**4a 订单不存在**

**输入**：`订单31415一直没有物流更新，帮我查一下`（31415 不在 seed 数据中）

**预期现象**
- 工具调用：`query_order`（`order_id` 为 `31415`）。工具返回 `{"error": "订单 31415 不存在，请确认订单号是否正确"}`（来自 [`tools.py`](../tools.py)）。
- 不会调用 `create_ticket`；回复提示用户核对订单号。

**4b 知识库里没有的问题**

**输入**：`你们支持分期付款吗？`

**预期现象**
- `knowledge/` 的 13 篇文档里没有分期付款的内容（未确认模型会怎么走）。两种可能：
  - 模型调用 `search_knowledge`：检索片段一栏会显示"未找到"并标出"已降级"（全部结果低于相似度阈值时）；也可能命中相似度偏低但仍高于阈值的无关片段，此时 rag 返回的提示会要求模型告知用户知识库中没有相关内容。
  - 模型不调用任何工具，直接说明不在服务范围内。
- 无论哪种，回复都不应编造分期付款政策；没有 `create_ticket`。

**镜头重点**：展示"不知道就说不知道"，而不是编造。如果 4b 恰好没有出现"已降级"标记，可以换成一个更明显离题的问题再试，以界面实际显示为准。

## 录制建议

- 浏览器窗口宽度约 480~600 px，缩放 100%，隐藏书签栏。
- 总时长 60~90 秒：对话 1 + 2 + 3 + 4 依次连续录，每条之间点"新会话"。执行详情在每条回复后展开 3~5 秒。
- 导出为 `docs/demo.gif`（README 已引用该路径）。

## 演示后清理（可选）

对话 2 会往 `tickets` 表写入一条工单。清理方法（`agent` / `agent_demo` 为 `.env.example` 中的默认用户名和库名，改过则按实际填写）：

```bash
docker compose exec db psql -U agent -d agent_demo -c "SELECT ticket_id, order_id, reason, created_at FROM tickets ORDER BY ticket_id;"
```

确认要删的工单号后：

```bash
docker compose exec db psql -U agent -d agent_demo -c "DELETE FROM tickets WHERE ticket_id = <工单号>;"
```
